## 2. 实际干预和四种量的区别

对于覆盖同一原区域r的不同物理客户端i和j，S_i/S_j是其实际下发模型，U_i是发送slot真实SGD后的上传。诊断只在接收模型副本中施加：

`delta_i,r = mask_r(U_i - S_i)`

`alpha_i,r = n_i / sum(n_k for ALL upload slots covering r)`

`S_tilde_j = S_j + alpha_i,r * delta_i,r`。

九个区域及其中真实参数形状沿用原实现，注入包含该区域原本拥有的参数，不细化或扩展正式Gate。只给不同物理客户端共同拥有的区域注入；同一客户端的重复slot不能自行构成比较支持。

接收端类别c的`delta_CE`是同一固定batch上，注入后CE减去原始下发模型CE；正值为恶化，负值为改善。模型仍一次看到固定的32张混合类别batch，随后按类别汇总loss，**不按类别重分batch**。BN虽然不跟踪运行统计，但两次使用相同输入batch；每个baseline的重复评估最大CE差均为0。

四项量分别记录：

1. **方向余弦**：发送slot区域增量与去重LOO参考的余弦；同时另记发送/接收slot的两两余弦。这两个参考不同。
2. **当前Q**：沿用现有类别条件概率响应变化的物理客户端区域分歧分数，不使用新CE计算或改写Q。
3. **发送端自身学习收益**：`CE(S_i, sender_probe) - CE(U_i, sender_probe)`，衡量发送端完整本地SGD。
4. **接收端功能影响**：`CE(S_tilde_j, recipient_probe) - CE(S_j, recipient_probe)`，衡量原生尺度下某个区域增量的条件影响。

完整SGD收益与缩放后的区域影响尺度不同。后者是固定下发模型上的单项贡献测量，不能直接推导移除该发送者、整轮聚合或最终测试精度的结果。

## 4. 当前Q对接收端CE的解释价值

第2–5轮共122对，21个不同发送客户端、29个接收客户端：平均接收端`delta_CE=-0.005324`，中位数-0.000674，范围[-0.084934,0.035264]。

**122对的Q全部大于0，但其中86对CE改善。** 改善组Q均值0.008069，恶化组0.009249，分布高度重叠。Q>0本身不能被解释为接收端有害。

|固定评分，越高越预测CE恶化|第2–5轮AUC|
|---|---:|
|当前Q|0.5598|
|负的有符号LOO余弦|0.5468|

分析在获得CE结果前固定：比较方向单变量与方向+Q，用逐轮留出OLS预测**有符号CE变化**；只按训练fold标准化，不做模型、阈值或参数搜索。两种模型另以同样的alpha、缩放增量L2、接收端baseline CE、发送端完整SGD收益作控制。预设最低描述性分析条件为改善/恶化各至少10对、至少10个发送者和3轮；主要样本满足，冲突子集不满足。

|逐轮留出模型|方向模型MSE|方向+Q的MSE|加入Q后的变化|
|---|---:|---:|---:|
|无额外控制|0.000253655|0.000256203|误差增加1.00%|
|相同幅度和自身收益控制|0.000246666|0.000247630|误差增加0.39%|

只保留当前Q实际比较过的接收端类别时，仍保留122对，其中101对改善、21对恶化；Q的AUC为0.5075，加入Q后的留出MSE增加4.12%（相同控制下增加2.18%）。因此，本次没有观察到Q在方向之外稳定降低预测误差。

这些是单种子、训练早期、相关配对上的描述性结果，未作独立样本显著性推断，也不能外推到后期真正冲突区域。微小AUC优势和MSE差异均不作为Gate选择依据。

### 相同发送者，对不同接收者可产生相反影响

主要样本中，64个发送slot—区域—轮次上下文里，58个测了至少两个不同接收者，其中**23个同时产生CE改善和恶化**。它们使用相同发送增量、alpha、当前Q和LOO方向分数。接收端状态/容量/训练分布改变了功能影响，单一发送者分数不能指定哪一个接收者受损。

发送端自身完整SGD收益在122对中均为正（配对加权均值1.3533，范围0.5354–2.1065），包括全部36个接收端恶化案例。自身学习收益与对他人的影响必须分别测量。

主要样本的1952个类别记录中，1003个改善、948个恶化、1个数值中性，说明平均改善也可能包含类别间取舍。当前探针限于接收端已有训练类别，无法评价它没有样本的类别上的互补知识。

## 6. 若用于真实在线聚合，额外成本是什么

本次模拟器可以读取各客户端训练分区。真实FL必须由接收客户端本地生成并保存自己的固定探针，原始图像和标签留在客户端；服务器组织增量分发并接收类别级CE反馈。

在本次固定抽样预算下：

|项目|5轮实测/载荷代理|
|---|---:|
|接收端注入评估|156个32样本前向batch|
|缓存baseline与重复零控制|88个前向batch|
|发送端完整SGD后自身收益评估|31个前向batch|
|合计|275个前向batch|
|只做接收端影响时的不同接收slot baseline|42个前向batch|
|单轮单个物理接收者最多注入请求|9个|
|区域增量额外下行，float32未压缩|636,464,464字节，约636.46 MB|
|类别反馈，uint32类ID+uint32计数+float32 CE差|29,952字节，不含头部|

baseline可按接收slot缓存；重复零控制和发送端收益属于本次核验/解释开销。接收者需要保留实际下发状态或等价快照，并在模型副本上试算，不能把探针注入后的参数继续用于SGD。

普通Native参数载荷同预算下约1,046,789,888字节/单向，双向约2,093,579,776字节；因此额外未压缩增量下行约为原单向载荷的60.80%，或原双向载荷的30.40%。反馈很小，**增量下行和额外协作阶段才是主要通信代价**。消息版本、区域ID、尺度、错误/缺失反馈等协议开销尚未计入代理。

如果这些反馈用于决策，还需要“上传完成→给接收者发送候选增量→本地成对评估→返回CE”的额外往返及客户端可用性；当前实现没有把它接入聚合。弱设备的额外前向、保存下发状态和副本显存需要分别评估，不能默认服务器读取私有数据或免费完成测量。

GPU0 RTX4090上本次训练/测量区段35.92秒，诊断函数合计3.38秒（含真实更新快照I/O及只读方向/Q计算），PyTorch峰值allocated1577.30 MiB、reserved1720 MiB。这个模拟器计时不是实际异构客户端和网络环境的在线开销基准。
